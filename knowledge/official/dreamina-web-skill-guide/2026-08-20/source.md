# 【自定义技能】即梦工具集说明

> **文档目标**：帮助您快速理解即梦 Agent 工具集，并写出一个能跑通的自定义技能（skill）
> 
> **适用读者**：对技能框架有基础理解，并希望**独立撰写技能**的创作者
> 
> **预计阅读时长**：约 8 分钟

本文档分四部分：

1. **工具速查**：12 个工具的定义与用途，看完知道有哪些"积木"
2. **创作基本准则**：图片与视频创作的默认参数、多样性与流程纪律
3. **典型工具链路**：常见技能需求对应的工具组合，看完知道"积木怎么搭"
4. **技能写作参考**：撰写规范、交付格式与完整示例

### 阅读提示

用户使用中文创作 Skill 时，只阅读并遵循中文版；用户使用英文创作 Skill 时，只阅读并遵循英文版。除非用户明确要求双语输出或翻译，不要在两个版本之间互相转译要求。

## 工具速查

### 图片生成与编辑

| 工具名 | 用途 |
| --- | --- |
| text2image | **文生图：**仅基于文本提示词生成图片 |
| image2image | **图生图：**以 1 张或多张图片为参考，进行改造、融合或风格延续 |
| foreground_segmentation | **抠图：**从已有图片中提取主体、去除背景 |
| image_super_resolution | **超分：**提升已有图片的清晰度与分辨率 |

### 视频生成与剪辑

| 工具名 | 用途 |
| --- | --- |
| text2video | **文生视频：**仅基于文本描述，直接生成视频；<br>适合：快速原型制作、简单动态演示等相对简单的生视频场景，对创作对象没有具体的形象要求。<br>控制项情况：全时长可用、全分辨率可用、全比例可用 |
| image2video | **首帧生视频：**以单张图片为**首帧**，生成续写视频；<br>适合：将静态图片转化为动态视频、为分镜中每个场景图生成对应视频片段等生成场景，与R2V相比，强调首帧画面的高度一致性<br>控制项情况：全时长可用、全分辨率可用、比例严格遵循首帧 |
| start_end2video | **首尾帧生视频：**给定首帧和尾帧，生成中间过渡视频；<br>适合：需要精确控制视频起始和结束画面、创建转场效果（如产品从远到近的展示）等场景，是首帧生视频的一种额外形式<br>控制项情况：全时长可用、全分辨率可用、比例严格遵循首帧、尾帧 |
| multi_frame2video<br> | **多图生视频：**以多张图片为关键帧串联生成视频<br>适合：需要精确控制视频起始和结束画面、创建转场效果（如产品从远到近的展示）等场景，是首帧生视频的一种额外形式，类似多个首尾帧拼接的效果<br>控制项情况：特殊时长、全分辨率可用、比例完全对齐每帧 |
| multi_modal2video<br> | **多模态视频生成：**混合使用图片、视频、音频等多模态素材生成视频；prompt 中可配合 `@图片N`、`@视频N`引用增加准确性<br>控制项情况：全时长可用、全分辨率可用、全比例可用 |
| clip_join<br> | **视频拼接：**拼接多段已有视频，或做简单后处理；<br>适合：在流程最后一步将所有片段合成最终视频、需要为视频添加背景音乐的场景 |

## 创作基本准则

### 默认设置继承原则

在调用图片或视频生成工具，或改写已有 Skill 时，必须先区分"用户显式要求""用户已有默认设置""原 Skill 已声明的运行默认值"和"本文档建议默认值"。

优先级为：用户本轮明确要求 > 用户账号 / 当前面板 / 当前会话中的默认模型、尺寸、比例、张数等 > 原 Skill 已声明的模型、清晰度、比例、数量等运行默认值 > 工具 schema 与平台能力约束 > 本文档建议默认值。

本文档中的默认值只在用户没有明确要求、无法读取或确认其已有默认设置，且原 Skill 也没有声明对应运行默认值时使用。若原 Skill 的默认模型、尺寸、比例或数量与工具 schema 或平台能力冲突，应说明冲突并向用户确认，不得静默覆盖、删除或替换。

### 图片创作参数继承与缺省策略

| 参数 | 缺省策略 | 例外条件 |
| --- | --- | --- |
| 模型 | 优先沿用用户账号 / 当前面板 / 当前会话中的默认模型；**改写已有 Skill 时，优先保留原 Skill 已声明的模型** | 仅当当前模型不支持任务所需能力，或与工具 schema 冲突时，说明原因并询问用户是否切换；禁止静默换模型 |
| 分辨率 / 清晰度 | **优先沿用用户已有默认尺寸或原 Skill 已声明的清晰度**；若都缺失，再使用 4K 或所选模型支持的较高档位 | 受所选 / 面板模型在工具 schema 中的能力约束；内容简单且不影响质量时可适度下调；面板模型与面板分辨率不兼容时必须反问，禁止默默降级或换档 |
| 生成张数 | **优先沿用用户已有默认张数或原 Skill 已声明的数量结构**；若都缺失，再生成 4 张 | 仅当用户以明确数字指定张数时才按其要求执行，例如"生成 1 张""只要 1 张""给我 2 张"；"要一个""给我一个版本""再来一个"等未出现具体数字的单数表达不视为指定 1 张；若原 Skill 将数量绑定到角色、步骤或交付结构，应保留该结构 |
| 画幅比例 | **优先沿用用户已有默认比例或原 Skill 已声明的主比例**；若都缺失，再按用途推断 | 手机竖版 9:16，常规海报 / 人物 3:4，方图 1:1，横版场景 16:9；同一轮只推断一次，同批所有图片必须使用同一比例，除非用户明确要求多比例 |
| 并行生成 | 是 | 仅在存在明确前后依赖（如先生成主体再产出变体、先生成参考图再改图等）时允许串行；原 Skill 已定义任务依赖或角色并行方式时，应优先保留 |
| 风格 | 根据用途和子任务自动推断 | 用户明确指定风格、存在参考图约束，或原 Skill 已声明 Style Anchor / 艺术指导时，以这些要求为准 |

### 图片多图多样性纪律

- 当按缺省策略生成 4 张时，必须在 Prompt 与方案层面形成有效差异，不得提交 4 条高度相似的 Prompt。
- 可差异化维度包括：构图视角、景别、光位与光比、冷暖关系、色彩基调、场景层次、主体姿态和表现方式。
- 遇到高度具体的 Prompt、强约束参考图，或专项 Skill 要求严格一致时，关闭大幅差异化，仅允许细节级微调。
- 优先级：用户明确要求 / 参考图约束 / 专项 Skill 一致性要求 > 通用多样性。
- 生成前必须逐项检查分辨率、张数、比例、并行策略以及 4 个方案的差异点；任一项缺失不得提交。

### 视频创作流程纪律

1. **视频生成阶段禁用 BGM**：参考素材与视频片段生成阶段禁止生成任何 BGM / 背景音乐；只有在最终剪辑阶段用户明确选择需要配乐时，才把配乐偏好交给剪辑流程处理。
2. **比例收集延迟**：只有在分镜 / Clip 表完成并经用户确认、即将进入参考素材生成或分镜生视频阶段时，若仍缺少视频比例，才通过表单补齐。
3. **分镜生视频工具纪律**：有参考素材时默认使用 `multi_modal2video`；普通素材按输入顺序在 Prompt 中写作 `@图片N` / `@视频N` / `@音频N`；来自用户参考主体的角色、物品、产品或场景必须写作 `<subject>主体名称</subject>`，禁止改写成 `@图片N`；同时必须把该主体对应的真实 `resource_id` 填入对应的图片输入参数。

## 典型工具链路

按复杂程度，skill 分为**原子型**（封装专业知识或个人风格）和**复合型**（多工具串联完成完整流程）。

### 原子型 skill（专业知识 / 个人风格的封装）

把一套领域知识（打光方法、构图法则等）或个人风格偏好（视觉调性、叙事节奏等）固化为 Skill，让后续生成内容具备稳定且独特的调性。这类 Skill 既可以不直接调用工具，也可以只围绕单个工具做定制化封装；两种形态都能被复合型 Skill 复用。

| 技能类型 | 定义 | 适用场景 | 示例 |
| --- | --- | --- | --- |
| 知识 / 规则型 | 仅包含领域知识或风格要求，不调用工具 | 固定工作流指导、质量标准规范、风格指南 | 「日系风格人像构图法则」「好莱坞三幕式剧本结构」 |
| 单工具封装型 | 针对单个工具沉淀专业提示词模板 | 简化某个复杂工具的使用、沉淀特定领域的提示词 | 「产品广告图文生图模板」「情感短片视频提示词生成器」 |

### 复合型 Skill（多工具串联）

- 典型图片场景：

| **场景** | **典型调用链** |
| --- | --- |
| 素材处理并生成高清图 | image2image → foreground_segmentation → image_super_resolution |
| 需先搜索参考再生图 | creation_agent_search → text2image |

- 典型视频场景：

| **场景** | **典型调用链** |
| --- | --- |
| **经典长视频生成链路（>30s）** | generate_form_for_info_collection → 剧本创作 → 分镜设计 → text2image / 上传已有素材 → 并行提交 image2video -> video_editor |
| **图片驱动的视频片段生成（≤30s）** | generate_form_for_info_collection → text2image → image2video |

## Skill 写作参考

### 撰写规范

1. **工具调用显式写出**：在对应步骤中明确写出调用的工具名（如 `image2image`），并说明分支条件。
2. **阶段划分**：明确区分**交互阶段**（需用户参与）和**执行阶段**（自主完成），边界清晰。
3. **字段表格**：用「字段 / 必填 / 缺失时处理」三列表格定义信息收集项，逻辑一目了然。
4. **必填 vs 可选要分清**：必填字段缺失时必须打断流程提示用户；可选字段给合理默认值，避免逼问。

### 交付格式约束

以下约束是提交前必过的强校验，任一条不满足都不得交付：

1. **`name`（技能名 / Skill name）**：`name` 是当前 Skill 的唯一提交名称，应使用与创作者当前创作语言一致的能力导向名称。使用中文创作 Skill 时，按中文命名习惯填写；使用英文创作 Skill 时，按英文命名习惯填写。必要的官方品牌、模型、协议、行业缩写或专有名词可保留原文。
  - 中文创作：使用中文优先的能力导向名称，避免纯英文、纯拼音、英文能力描述，或用多个 `-` 拼接的拼音 / 英文 slug。中文名称示例：`Logo-样机自动生成技能`。
  - 英文创作：使用自然英文的能力导向名称，避免拼音、机器翻译腔、过长 slug，或把中文音译成英文 / 拼音后再拼接。英文名称示例：`narrative-film-storyboards`。
  - 长度 1–30 个 Unicode 字符（每个汉字、字母、数字、`-` 各计 1 个字符）。
  - 字符白名单：汉字、英文字母、半角数字 `0-9`、必要的半角连字符 `-`。
  - 禁止任何空白字符，禁止 `.`、`·`、`_`、`/`、`\`、`:`、`：`、括号、引号、方括号、星号、其他标点、emoji 与 Markdown 包裹符。
  - `-` 只能出现在汉字、英文专名或数字片段之间，不得置于首尾，也不得连续出现。
  - 若名称中包含非主要创作语言的专名或缩写，应保持必要、紧凑，不得堆叠多个无关英文 / 中文片段。
2. **`description`（技能描述）**：500 字内单段，依次覆盖核心产出、触发场景与建议的不适用边界；不捏造未知规格，不写工具组合流水线，也不塞入完整流程。
3. **交付形态**：一个 Skill 对应且只对应一个独立的 `.md` 文件，且必须采用 frontmatter 格式：
  - 文件开头以 `---` 起止的 YAML frontmatter 承接 `name` 与 `description` 两个字段；若 YAML frontmatter 中存在其他字段，应删除，仅保留 `name` 与 `description`。frontmatter 结束后紧跟 `# <技能名称>` 作为一级标题，标题之后即完整正文。
  - `name`、`description` 与正文能力、边界、产物、流程保持一致；下方"完整示例：Logo 样机自动生成"即为标准格式参考。
  - 禁止生成任何 Python 测试脚本、示例数据脚本或调用脚本。
  - 禁止生成文件夹或多文件结构（无 `skill/`、`assets/`、`tests/` 等目录，也不拆分成多个 `.md`）。

### 完整示例：Logo 样机自动生成

```Markdown
---
name: Logo-样机自动生成技能
description: 本技能输出Logo多场景落地展示效果图，支持自定义材质、环境、灯光、特效。当用户提到「做Logo样机」「生成Logo应用图」「Logo印在XX上的效果」时调用，不处理纯Logo设计。

---
# Logo-样机自动生成技能

## 角色定位
我是Logo样机效果图自动生成助手，专注于根据Logo素材或文字描述生成真实商业质感的多场景落地展示效果，帮用户快速预览Logo在实际应用中的视觉呈现。

## 工具使用规范
| 工具名称 | 调用时机 | 说明 |
|---------|---------|---------|
| `generate_form_for_info_collection` | 信息收集阶段 | 收集用户缺失的关键信息 |
| `text2image` | 无Logo素材仅文字描述时 | 生成2张透明底Logo候选 |
| `image2image` | 有Logo素材或已确认Logo后 | 生成3张差异化样机效果图 |

## 执行流程
分为交互阶段（步骤1–3，需用户参与）和执行阶段（步骤4–5，自主完成）

### 一、交互阶段
#### 步骤1：信息提取
需要收集以下关键信息：
| 字段 | 必填 | 缺失时处理 | 默认值（按场景） |
| --- | --- | --- | --- |
| Logo素材/文字描述 | 是 | 提示用户上传或描述，停止流程 | - |
| 应用场景 | 是 | 提示用户指定（门头/名片/包装/墙面…），停止流程 | - |
| 材质偏好 | 否 | 按场景设置默认：门头→亚克力发光、名片→铜版纸、墙面→哑光金属 | 场景默认值 |
| 环境细节 | 否 | 按场景设置默认：门头→临街商铺、名片→极简办公桌面 | 场景默认值 |
| 灯光氛围 | 否 | 按场景设置默认：门头→暖白夜景、名片→自然光 | 场景默认值 |
| 特殊效果 | 否 | 默认自然投影 | 自然投影 |

调用 `generate_form_for_info_collection` 收集信息，处理skip分支。

#### 步骤2：信息确认
将提取/补充后的字段结构化呈现，标注哪些是默认值，等待用户确认或修改。

#### 步骤3：方案确认
告知交付物为3张4K候选图，风格规格为真实商业摄影质感，用户确认后进入执行。

### 二、执行阶段
#### 步骤4：执行生成
**全局约束**（重要，必须满足）：
- MG-1：Logo完整、无裁切、无变形、识别度高
- MG-2：材质质感符合指定要求
- MG-3：光影真实统一，阴影方向匹配光源
- MG-4：无多余水印或干扰元素
- MG-5：分辨率 ≥ 3840×2160

工具调用规则：
- 无Logo素材，仅文字描述 → 使用 `text2image` 先生成2张透明底Logo候选
- 有Logo素材或已确认Logo → 使用 `image2image` 生成3张差异化样机，并行提交生成任务

#### 步骤5：质量检查
按 MG-1 ~ MG-5 逐项核查，不通过则补充约束后重新生成，最多重试3次。

## 追问原则
- 若用户已明确关键信息，直接使用，无需追问；
- 若缺失必填信息，通过表单收集，同时提供场景默认值供用户一键确认；
- 用户可随时覆盖任意参数，技能响应调整。

## 全局约束
1. 必须保证Logo完整显示，无裁切、无变形，识别度高；
2. 材质、环境、灯光效果必须符合用户指定或场景默认；
3. 光影真实自然，阴影方向与光源方向一致；
4. 不得添加多余水印、文字或干扰元素；
5. 分辨率必须不低于3840×2160；
6. 严格遵守内容安全规则，禁止生成违规内容。
```
