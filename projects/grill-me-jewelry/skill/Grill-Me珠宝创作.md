# Grill-Me珠宝创作

分为**交互阶段**和**执行阶段**。交互阶段完成四轮探索、候选矩阵和独立确认；执行阶段只使用已确认简报生成设计图、检查数量与质量并交付。

参数优先级：用户本轮明确要求 > 当前面板或会话默认设置 > 本技能声明的默认值 > 工具能力约束 > 通用缺省值。不得用本技能默认值覆盖用户已有设置。

`generate_form_for_info_collection` 只收集文字、单选和多选信息；图片、草图、裸石图、已有珠宝图或其他附件必须由用户在对话中上传或使用当前会话已有资源，不得通过表单收集。

## 一、触发与路由

| 条件 | 路由 |
|---|---|
| 用户明确说“Grill Me 珠宝”“深度问我”“帮我探索到底要设计什么” | 强制完成四轮探索，即使部分信息已知 |
| 工作流、珠宝身份、输出形态三者都无法从文字和素材推断 | 进入四轮探索 |
| 工作流已知，只缺品类、材质或一两个关键字段 | 不进入 Grill Me；用一次合并表单补齐后执行明确任务 |
| 品类、设计目标和输出已经清楚 | 不进入 Grill Me；按明确需求直接执行 |

显式 Grill Me 请求本身就是充分触发条件。不得因为用户已给出一两项信息而缩短为普通问卷。

## 二、工具映射

| 工具 | 使用时机 | 下一步 |
|---|---|---|
| `generate_form_for_info_collection` | 四轮探索、简报确认或修正受影响字段 | 更新累计状态，不重复已解决问题 |
| `creation_agent_search` | 已确认简报需要文化、工艺或风格事实依据 | 把结果转成原创设计约束，不复制品牌款 |
| `text2image` | 从零开始或只有文字构思 | 每个候选单独生成并进入 QA |
| `image2image` | 有草图、已有珠宝、裸石、材料或元素参考 | 明确输入角色、保留项和可变项后生成候选 |
| `image_super_resolution` | 用户要求高清且结构检查已通过 | 输出高清候选，不用超分掩盖结构错误 |

图片默认使用 4.7 模型的 2k 版；只有用户与当前面板都没有模型设置时才应用该默认值。默认输出白底或极浅灰白背景的单件珠宝设计图；用户明确要求佩戴、场景、包装或广告展示时才改变背景。

## 三、交互阶段

### 3.1 状态规则

- 四个探索阶段必须各完成一轮提交，之后才能进入独立确认轮。
- 每轮只问 1-4 个当前可回答字段，不得超过 4 个。
- 已知事实不重复询问；该阶段基础事实已知时，改问本阶段更深的未决问题，不跳过阶段。
- 每轮提交后，用一段短摘要重述新增事实和累计结论，再进入下一阶段。
- 早先答案保持有效，只有用户明确修正时才更新。
- 不替用户回答审美、意义、情感或取舍问题。
- 选择题提供“其他”与自定义文本路径。

### 3.2 第一轮：创作地基

调用 `generate_form_for_info_collection`，从下列字段选择最多 4 个未解决字段：

| 字段 ID | 目标 | 缺失时选项 |
|---|---|---|
| `workflow_family` | 原创设计、参考演化、草图成品化、裸石配款、展示图或其他 | 提供单选与其他 |
| `jewelry_type` | 戒指、项链、耳环、手链、吊坠、胸针、套装或其他 | 提供单选与其他 |
| `starting_point` | 从零、文字雏形、草图、已有珠宝、裸石/材料、元素/风格参考 | 提供单选与其他 |
| `delivery_count` | 交付数量 | `count_1`、`count_2`、`count_4`、`count_8`、自定义数量 |

用户已经用明确数量表达指定交付数时原样锁定，不得重问或缩减，例如“1款”“2款”“四款”“8张”。“一枚戒指”“做一个版本”“给我一个方向”等单数对象或版本表达不视为明确指定交付 1 款，仍须在本轮确认 `delivery_count`。

### 3.3 第二轮：意义内核

调用 `generate_form_for_info_collection`，根据未决状态从以下维度选择最多 4 个：

- `wearer_recipient`：佩戴者或赠予对象。
- `occasion`：日常、纪念、婚礼、典礼、收藏或其他场景。
- `emotional_intent`：克制、守护、力量、自由、浪漫、神秘等情绪目标。
- `story_symbolism`：故事、主题、意象或象征。
- `cultural_boundary`：必须尊重或避免的文化边界；仅在会改变设计时询问。

如果对象和场景已知，使用情绪、象征和文化边界等更深问题完成本阶段。

### 3.4 第三轮：设计语言

调用 `generate_form_for_info_collection`，从下列未决字段选择最多 4 个：

- `design_system`：高级珠宝、当代极简、古董、建筑、雕塑、有机、东方工艺等。
- `silhouette_motion`：几何、流线、包裹、放射、悬浮、非对称运动等。
- `visual_weight`：轻盈、平衡、饱满、戏剧化。
- `hero_material_gem`：主材质、主石、配石语言和金属颜色。
- `finish_craft`：镜面、哑光、錾刻、花丝、密钉、包镶、微珠边等。
- `reference_role`：用户素材分别用于结构、石材、风格、工艺、颜色或构图。

不得编造宝石等级、产地、证书、价格、品牌信息或附件中不存在的细节。

### 3.5 第四轮：变化与交付

调用 `generate_form_for_info_collection`，优先解决：

| 字段 ID | 内容 |
|---|---|
| `output_family` | 白底设计图、草图成品化、佩戴展示、系列探索或只要文字简报 |
| `locked_facts` | 品类、佩戴逻辑、核心故事、指定材质、必须保留结构 |
| `flexible_axes` | 轮廓、镶嵌、元素转译、宝石布局、负空间、表面工艺 |
| `exploration_spread` | 稳健、平衡、宽幅或实验性探索 |
| `required_asset_status` | 必须素材是否已上传；仅在执行依赖素材时使用 |

本轮最多 4 个字段。需要某张源图但尚未上传时，在表单外明确要求上传，并在素材到位前停止确认与出图。

## 四、候选矩阵

当 `delivery_count >= 2` 时，在确认前建立候选矩阵：

- 固定：珠宝品类、佩戴逻辑、核心故事、用户锁定材质和必须保留结构。
- 可变：轮廓、镶嵌结构、元素转译、宝石布局、负空间、表面工艺。
- 每个候选至少改变 3 个可见设计轴；只改形容词、颜色、背景、镜头或光线不算有效差异。
- 不得擅自加入可转换、双用或机械结构。
- 锁定项导致不足 3 个可变轴时，必须要求用户放宽限制或把数量改为 1，不得伪造差异。

默认分支顺序：

| ID 顺序 | 分支角色 | 差异方向 |
|---|---|---|
| 1 | 商业核心 | 清晰焦点、可佩戴比例、克制元素转译 |
| 2 | 雕塑重构 | 重建轮廓、加强体量、改变负空间 |
| 3 | 工艺签名 | 改变镶嵌系统、表面处理和材质连接 |
| 4 | 叙事重译 | 用不同可见结构表达同一故事 |
| 5 | 轻量化 | 降低体量、增加通透、简化配石节奏 |
| 6 | 建筑几何 | 模块秩序、结构重复、清晰空间逻辑 |
| 7 | 高珠戏剧 | 放大尺度节奏、丰富宝石编排和仪式感 |
| 8 | 系列节奏 | 重复签名单元，形成可延展系列语言 |

使用前 N 个角色作为起点，再按用户确认的可变轴改写。每个候选使用稳定 ID `GM-01` 至 `GM-N`。

## 五、独立确认门

四轮完成且必须素材已到位后，输出共享简报、锁定项、可变轴、数量和候选矩阵，再调用 `generate_form_for_info_collection`：

| 字段 ID | 选项 |
|---|---|
| `brief_action` | 确认并执行 / 修改简报 / 只保留文字简报 |
| `brief_corrections` | 可选修正文本 |

- 确认前禁止调用 `text2image`、`image2image` 或创建任何生成任务。
- 选择“修改简报”时只回到受影响字段，保留其他答案，更新候选矩阵后再次确认，不重跑四轮。
- 选择“只保留文字简报”时直接交付确认版简报，不调用图片工具。

## 六、执行阶段

### 6.1 工具路由

| 已确认输入 | 执行 |
|---|---|
| 从零开始或只有文字构思 | 每个候选独立调用 `text2image` |
| 草图、已有珠宝、裸石、材料、元素图或产品图 | 每个候选独立调用 `image2image` |
| 需要文化、工艺或风格事实依据 | 先调用 `creation_agent_search`，转成原创约束后生成 |
| 展示图且已有确认产品图 | `image2image` 锁定产品身份，只改变佩戴者、场景或构图 |
| 展示图但尚无产品图 | 先生成并检查珠宝设计图，再基于通过结果生成展示图 |
| 用户要求高清 | 结构与身份检查通过后调用 `image_super_resolution` |

候选之间没有依赖时并行生成；“先产品、后展示”和“先结构检查、后超分”必须串行。

### 6.2 候选提示词规格

每个 `GM-xx` 的提示词必须包含：

```text
任务目标：当前候选要解决的设计方向。
输入角色：文字 / 草图 / 裸石 / 已有珠宝 / 元素 / 风格参考。
必须保留：品类、佩戴逻辑、故事、主石、指定材质、锁定结构。
本候选变化：至少三个可见设计轴。
珠宝结构：镶嵌、支撑、连接、链路、戒臂、扣具或佩戴结构。
材质工艺：金属、宝石布局、表面处理、工艺密度和连接方式。
画面：单件产品、白底或极浅灰白、真实金属反射、宝石火彩、自然接触阴影。
禁止：文字、Logo、水印、证书、价格、无关道具、品牌复刻、漂浮结构、塑料感、未声明宝石。
```

有参考图时，明确每张图的角色、保留项与允许变化，不把风格参考误当产品身份。

### 6.3 Manifest 与数量守恒

```Markdown
| candidate_id | branch_role | tool | input_role | locked_facts | changed_axes | status | retry_count |
|---|---|---|---|---|---|---|---|
```

- 一款对应一张独立图片；合集图不能抵扣数量。
- `requested_count` 等于确认的 `delivery_count`。
- 每个 ID 最终只能是 `done` 或 `failed`，失败项不得从清单消失。
- `missing_count = requested_count - done_count`；大于 0 时不得声称完整交付。

## 七、质量检查与重试

逐项检查：

- 品类和佩戴逻辑正确。
- 主石、指定材质、故事和锁定结构保持一致。
- 每个多候选分支至少有 3 个可见差异轴。
- 镶嵌、支撑、连接和比例具有可制作逻辑。
- 单件图无多余珠宝、拼图、文字、Logo、水印或虚构参数。
- 数量汇总与 Manifest 一致。

失败时保留原 `GM-xx`，记录原因并只修复对应约束，最多重试 2 次。结构错误不得用超分处理；连续失败后标记 `failed` 并计入 `missing_count`。

## 九、触发示例

- “用 Grill Me 珠宝一步步问我，我还不知道到底想设计什么。”
- “帮我做个珠宝，完全没方向，你深挖一下。”
